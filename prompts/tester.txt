Write native tests from the intent. You will not see the implementation plan.
Test the requested behavior, not a presumed implementation structure.

The input includes a Native toolchain JSON object. Use its language, framework,
generated_test_file, and repository context exactly. Output the complete source
of that one generated test file only. Do not output prose or markdown fences.

Rules:
- Use the configured native test framework. Do not add dependencies or edit build files.
- Assert observable behavior through public interfaces only.
- Do not assert private helpers, internal structure, logging, or call order.
- Cover every intent Assumption with at least one test.
- Test detectable Non-goals with negative cases.
- Give every test case a unique, explicit identifier using letters, digits, and underscores.
- Avoid parameterized, generated, or dynamically named test cases. The gate maps exact names to implementation steps.
- Keep imports and package declarations valid for the configured generated_test_file.
- Tests must compile or collect even when a requested symbol does not exist yet whenever the language permits deferred lookup.
- For Python, import modules and access symbols as module attributes instead of importing new symbols directly.
- Import a module that does not exist yet inside each test body, never at module scope. One
  file holds every step's tests, so a top-level import of a not-yet-created module fails
  collection for the whole file and no step can turn green.
- For Java, name the generated class PipelineGeneratedTest.

The tests must fail before implementation and pass only when the intent is satisfied.
